# 807 班級看板（Firebase 版）

本專案使用 Firebase Hosting 發布網站、Cloud Firestore 保存班級資料，並以 Firebase Authentication 保護教師管理頁。

## 網頁

主要網址：https://qfmclass-807.web.app/

教師端：https://qfmclass-807.web.app/teacher.html

原網址 https://colabprogram-c8014.web.app/ 保留；兩個網址沿用同一個 Firebase 專案、資料庫與教師帳號，不需搬移資料。新網址首次使用需重新登入，手機桌面捷徑也可從新網址重新加入。

- `board.html`：學生端班級看板。
- `teacher.html`：教師管理後台。
- `book.html`：聯絡簿繳交登記。
- `games/index.html`：互動遊戲室；「追光點點」提供移動圓點挑戰、「地鼠出沒」提供 6 欄 × 5 列的打地鼠遊戲、「圈叉對決」提供 2 × 2 排列的四桌獨立 OX 棋盤。遊戲皆支援觸控，可由看板「互動區」進入。

## 教師登入

教師端只需輸入校內帳號前段與密碼，系統會自動補上 `@qfm.kh.edu.tw`。資料庫規則僅允許此網域的已登入帳號修改班級設定與建立課程任務；學生追加事務使用以下獨立流程。

## 可調整工作與分組人數

- 教師端「午餐小組 → 調整人數與成員」可分別設定三組的需要人數（1～60 人），不再固定每組 8 人。已編入的人員不會因修改人數而被自動重排；若要縮小到少於已編人數，請先移出學生。
- 選學生後按「移入這組」可移往有空位的小組，點選另一組學生仍可交換；「移出目前組別」會放回未編組。每組需要人數不含每週都參與的固定協助人員。
- 「固定協助人員」可複選或全部取消；從固定協助移除的人員會先列為未編組，供教師重新安排。
- 新學生不自動編組，刪除學生則釋出既有分配名額，不會把其他人移到別組。統計以實際名單計算，缺號不算人數。
- 教師端「值日生」可設定每日人數（上限為實際學生人數），儲存後選今天的起始人員；後續依所設人數在上課日輪替，假日跳過。
- 打掃工作已有「點選工作 → 修改內容 → 需要人數」；班級幹部／各科小老師已有每個職務的需要人數，均可個別調整。
- 設定隨教師資料同步到 Firebase，學生端只顯示結果。舊午餐設定預設保留原三組、每組 8 人及 14／24 號協助；舊值日生預設維持每日 2 人。

測試：`node scripts/test-adjustable-groups.mjs`。

## 學生轉出／封存

- 教師端「班級名單」中，已儲存學生的移除按鈕改為「轉出／封存」。確認日期後，歷史請假、課程繳交、聯絡簿紀錄會與在校名單分開保存；學生不再出現在學生端或人員選單，工作、午餐、值日生與幹部名額會釋出，其他學生不會被重新分配。
- 點選「轉出／封存」標籤可查看封存紀錄，請假按月份整理。封存資料只有教師帳號可讀取，沒有永久刪除操作。
- 「恢復在校」可指定空座號，帶回歷史紀錄；工作與職務不自動取回，需重新安排。新生使用舊座號時，不會繼承原學生的繳交狀態。
- 已在校學生不能以批次貼上或直接清空姓名移除；請使用封存流程。變更既有座號也需先封存再恢復，避免紀錄錯置。
- 封存與恢復都會先建立還原點，並在同一筆交易內完成資料變更，其他裝置的舊畫面會被要求重新載入。私人封存資料獨立保留，不隨整班還原點刪除。

## 女廁三組共同清潔

- 女廁保留六組上下相連的兩間馬桶，馬桶格內不放人名；洗手台左下、地板右下，這兩處保留各自的人名區塊。共同清潔人員在圖下方分成三個獨立區塊，不限定到某組馬桶。
- 三組、洗手台、地板均可從「設定 → 修改內容」個別設定人數、名稱及工作說明；也可拖拉或點選學生分配、交換。這五項工作允許 0 人（尚未規劃），0 人區塊不能直接分配；提高人數後才能加入學生。
- 舊版逐項分配資料會優先保留洗手台、地板的原有人員，其餘平均帶入三組。若已合併成一個共同小組且沒有保留原工作對應，所有同學先依既有順序平均帶入三組，洗手台與地板從 0 人開始，由教師重新指定；不猜測舊職務，也不遺失或重複人員。
- 分組只進行一次。教師後續修改的人數、成員與名稱不會因刷新重新平均分組，其他分區不受影響。
- 學生端與 A4 下載總表採用相同配置。舊設定在教師端載入打掃功能後會自動整合儲存；學生端可先以新格式顯示，不會自行寫入資料庫。
- 此次發布須包含 Hosting 與 Firestore 規則（教師私人封存區）。測試：`node scripts/test-student-archive.mjs`、`node scripts/test-female-cleaning.mjs`。

## 學生追加每日事務

- 點選學生端「明日事項」→「新增事務」，輸入內容與教師端提供的今日四位數確認碼；一行一點，上限 500 字。
- 登記日期固定為今天，當天追加到明日事項，下一個上課日列入今日任務。週末及教師設定的假日不能從學生端新增。
- 新增為獨立紀錄，不覆寫教師內容。學生只能新增，包含自己新增的內容也不能修改或刪除；教師仍可管理資料。
- 確認碼與授權紀錄位於不可公開讀取的資料區，內容及授權一併提交。每日台灣時間午夜失效，舊修改／刪除授權已停用。
- 更新後請教師重新開啟「事項排程」，載入今日確認碼；原有當日代碼會保留並補上失效時間。
- 學生追加事務另存於 `tomorrowSubmissions`，不包含在教師設定的還原點中。

測試：`node scripts/test-student-task-additions.mjs`。本功能需一起發布 Hosting 及 Firestore 規則。

## Firebase 發布前設定

1. 在 Firebase 專案 `colabprogram-c8014` 啟用 **Authentication → 電子郵件／密碼**。
2. 建立教師帳號，例如 `teacher807@qfm.kh.edu.tw`。
3. 在 **Firestore Database → Rules** 貼上 `firestore.rules` 的內容並發布。
4. 使用 Firebase Hosting 發布此資料夾；`firebase.json` 已指定根目錄與 Firestore 規則。

`.firebaserc` 定義 `classboard`（新網址）與 `legacy`（原網址）兩個發布目標；一般 `firebase deploy --only hosting` 會同步發布兩站。若修改資料庫規則，使用 `firebase deploy --only hosting,firestore:rules`。兩站應保持相同網頁內容，避免舊網址留在較舊版本。

學生端資料為公開可讀。聯絡簿繳交與課程完成小卡可公開登記，但規則僅容許建立限定欄位的紀錄；班級名單、座位、課表、午餐、打掃、值日生與任務設定均只能由教師帳號修改。

## 教師資料還原點

登入教師端後，右上角「還原點」（手機為 ↶）可查看備份、手動命名建立或還原。

- 啟用後第一次登入建立初始還原點；每次成功修改雲端設定前自動備份，合計保留最近 30 個，超過時取代最舊備份。
- 可選「事項與請假紀錄」或「全部教師設定」。還原前會再備份目前資料，因此可還原回去。
- 還原時清除座位表的暫時缺席旗標，避免歷史旗標重新計入今日請假；歷史請假紀錄仍依選定範圍還原。
- 學生留言、個別繳交／完成紀錄、舊學生端登記事項及帳號密碼另行保存，不在此備份範圍內。
- 備份從啟用後開始累積，無法補回啟用前已遺失的資料。

儲存時只合併有修改的設定，並在交易中核對最新雲端內容。同一份資料若被其他電腦修改，會停止儲存並保留本機草稿；請先「下載本機資料」再「重新載入雲端」。本機下載檔含班級個資，請妥善保管。新規則會阻擋舊版頁面的覆寫，所有教師裝置發布後需重新開啟頁面。

測試：`node scripts/test-restore-points.mjs`。發布需同步部署 Hosting 與 Firestore 規則。

## 舊 Netlify 資料

Netlify 與 Firebase 是不同資料庫。首次切換時，請先保留舊網站資料，並在 Firebase 教師端逐項儲存名單與設定；Firebase 不會自動讀取 Netlify Blobs 中的既有資料。
